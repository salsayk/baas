Timese

Application screens (pages + modals/wizards)

One slide per screen. Each slide includes a screenshot placeholder.

Screenshot placeholders expect images in ./screenshots/ with names like pages-accounts.png or modal-account.png.

Hierarchy Overview

  • Account (tenant root) owns one or more Service Offices.
  • Each Service Office manages: Customers, Projects, Contracts, and Subcontractors.
  • Service Office Users are employees/subcontractors who get data access via assignments.

Access is enforced server-side by the API using the signed-in user’s account ownership.

Data Assignment Model

Service office user access is stored in service_office_users_data_authorization as “entity type + entity id”.

  • 2 = customer (entity_id = customer_id)
  • 3 = project (entity_id = project_id)
  • 4 = contract (entity_id = contract_id)
  • 100 = all future customers (entity_id = service_office_id)
  • 101 = all future projects for a customer (entity_id = customer_id)

UI Screens & Localization

  • Screens define logical UI screen names and optional descriptions.
  • Screen translations store per-language names/descriptions.
  • Screen permissions map user types to permissions per screen.
  • System lookups and Lookup values power enumerations across the UI.
  • Languages define direction (LTR/RTL).

Account Modal

Component: AccountModal

Purpose: Create or edit an account (tenant-level info + optional credit card fields in this UI).

Required: account_name, mobile_phone, email_address
Inputs: secondary_phone, card_holder_name, card_number, card_expiry_month, card_expiry_year, card_cvv
Status: choose via status buttons (status)

Account Wizard

Component: AccountWizardModal

Purpose: Guided creation of an account plus its first service office plus an initial service office user (with email verification step).

  • Tab 0 (Account): fill account_name, mobile_phone, email_address, status (plus optional card fields)
  • Tab 1 (Service Office): fill service_office_name, status (plus optional description/country)
  • Tab 2 (User): fill user_name, user_type, user_professional_grade, mobile_phone, email_address, status
  • Email verification: handled via the EmailVerificationModal flow.

Email Verification

Component: EmailVerificationModal

Purpose: Confirm a 6-digit code sent to the user email.

  • verification-code (6 digits)
  • Resend code button (cooldown handled in modal)

Service Office Modal

Component: ServiceOfficeModal

Purpose: Create or edit a service office under an account.

Required: service_office_name, account_id (unless fixed), status
Optional: service_office_description, country

Account Service Offices

Component: AccountServiceOfficesModal

Purpose: Manage service offices belonging to a single account.

Fields: Add/Edit delegates to ServiceOfficeModal (use its fields).

Customer Modal

Component: CustomerModal

Purpose: Create or edit a customer within a service office.

Required: customer_name, service_office_id, email_address
Optional: legal_id, mobile_phone, secondary_phone
Address: address_country, address_city, address_street, address_street_number, address_zip_code
Status: status buttons set status

Service Office Customers

Component: ServiceOfficeCustomersModal

Purpose: Manage the customer list inside a service office (table + open customer modal).

Fields: Add/Edit delegates to CustomerModal.

Project Modal

Component: ProjectModal

Purpose: Create or edit a project tied to a customer and service office.

Required: project_name, service_office_id, customer_id, project_scope_description, status

Customer Projects

Component: CustomerProjectsModal

Purpose: Manage projects for a given customer.

Fields: Add/Edit delegates to ProjectModal.

Contract Modal

Component: ContractModal

Purpose: Create or edit a contract, including “PP Proforma” fields.

  • Contract Details tab: contract_name, contract_description (optional), customer_id, contract_type, status, contract_start_date
  • Amount fields (if enabled by contract type): contract_amount_value, contract_currency
  • PP Proforma tab: pp_proforma_recurrence, pp_proforma_occasion, pp_initial_payment_reached_indicator, pp_initial_amount_value, pp_upper_cap_reached_indicator, pp_upper_cap_amount_value, pp_recurrence_initial_payment_reached_indicator, pp_recurrence_initial_amount_value, pp_recurrence_upper_cap_reached_indicator, pp_recurrence_upper_cap_amount_value

Validation ensures required fields are present and focuses the first invalid field.

Assign Contracts (Project)

Component: AssignContractsModal

Purpose: For a selected project, pick contracts to assign and drag to reorder the assignment list.

  • Checkbox per contract (select/deselect)
  • Drag selected contracts to change ordering
  • Save creates/updates project–contract pairs in the system

Subcontractor Modal

Component: SubcontractorModal

Purpose: Create or edit a subcontractor tied to a service office.

Required: subcontractor_name, service_office_id
Optional: contact_person_name, contact_person_phone, contact_person_email, contact_person_address
Status: status buttons set status

Service Office Subcontractors

Component: ServiceOfficeSubcontractorsModal

Purpose: Manage subcontractors within a service office.

Fields: Add/Edit delegates to SubcontractorModal.

Service Office User Modal

Component: ServiceOfficeUserModal

Purpose: Create or edit a service office user (employee) and optionally link a subcontractor.

  • user_name (required)
  • user_type (required; lookup)
  • user_professional_grade (required; lookup)
  • service_office_id (required; fixed/readonly in embedded contexts)
  • subcontractor_id (required only when user type indicates subcontractor)
  • mobile_phone, secondary_phone, email_address
  • status buttons

Service Office Users

Component: ServiceOfficeUsersModal

Purpose: Table view for all users of a service office, with Add/Edit user actions.

Fields: Add/Edit delegates to ServiceOfficeUserModal.

Assign Customers & Projects Wizard

Component: AssignCustomersProjectsWizard

Purpose: Assign data access for a service office user across customers, projects, and contracts.

  • Step 1 (Customers):
    • Toggle Assign all future customers automatically
    • Customer tiles: select/deselect customers (disabled when future-customer toggle is ON)
    • Toggle Assign all current customers (managed/derived)
  • Step 2 (Customers & Projects):
    • Per-customer accordion “Assign all future projects” toggle
    • Project checkboxes (disabled when future-customer mode is ON)
  • Step 3 (Contracts):
    • Project-linked contracts are displayed based on selected projects
    • Independent customer contracts checkboxes: select contracts that are not implied by project selection

System Lookup Modal

Component: SystemLookupModal

Purpose: Create or edit a lookup table used for enumerations.

  • lookup_table_name (required)
  • lookup_table_description (optional)

Lookup Values Modal

Component: LookupValuesModal

Purpose: Manage values in a specific lookup table (and optionally edit translations).

  • Add/Edit value: value_id, value_name
  • Translations tab:
    • Select language
    • Lookup translation fields: name, description
    • Per value translation: value_name (per selected value)

Screen Modal

Component: ScreenModal

Purpose: Create or edit a UI screen definition.

  • screen_name (required)
  • screen_description (optional)

Screen Translations

Component: ScreenTranslationsModal

Purpose: Add/update translated screen name/description for a chosen language.

  • Select language
  • name (required)
  • description (optional)

Screen Permissions

Component: ScreenPermissionsModal

Purpose: Assign which permission is granted to each user type for a screen.

  • Select User Type
  • Select Permission
  • Press Add to create mapping (prevents duplicates per user type)
  • Existing mappings are deletable

Language Modal

Component: LanguageModal

Purpose: Create or edit a language (LTR/RTL).

  • language_name (required)
  • direction (0=LTR, 1=RTL)
